# YAF development

[Running guide](README.md) · [Imported sources](../../docs/dev/sources.md)

## Layout and dependency choices

YAF.App compiles the website into YAF.dll. Sidecars preserve YAF library names;
YAF.Host owns Kestrel, Serilog and XDT. Its App project excludes orphan code-behind
files whose markup is absent. The imported tree keeps its own line endings.

- YAF.Data.PostgreSQL is the App's default backend; YAF.Data.SqlServer also builds.
  Each registers an unnamed factory, so load only one. Switch the App reference
  and the `yafnet` connection/provider together to change databases.
- OrmLite and dialect sidecars repeat `NETFX;NET481` from the imported build props;
  otherwise no PclExport implementation is selected.
- Published Lucene.Net packages replace the renamed vendored copy. YAF's Search
  service uses their namespaces; the DNN-specific assembly separation is unnecessary.
- Web API and OWIN hosting use Rehost counterparts. Core Web API, Identity and
  middleware use their shipped managed packages.
- OEmbed uses its .NET 10 async API. The synchronous BBCode caller runs it through
  Task.Run to avoid blocking continuations on the Web Forms synchronization context.
  Media rendering remains unassessed.
- YAF.Compat supplies CallContext, TableAttribute, dynamic-assembly creation and
  an impersonation shape that refuses execution; it provides no remoting contract.
- Image processing and registry-based admin inspection remain Windows-only.
  Syndication uses its modern package; unused Dynamic Data, WCF and COM+ references
  are omitted.

## Language version

Sidecar.props pins C# 13; YAF.App uses 14 for the `field` keyword. C# 14 span
conversions can rebind array Contains to MemoryExtensions inside OrmLite expression
trees, where a ReadOnlySpan node cannot be boxed. The library pin prevents that
binding change; a clean compile alone cannot establish runtime compatibility.

## web.config

The Host XDT removes runtime settings and system.net, selects PostgreSQL and
supplies an explicit machine key. Modern SmtpClient does not read mailSettings;
YAF writes verification mail into `App_Data/mail` explicitly. The copied upstream
recommended.web.config supplies the configuration normally generated by installation.

An empty database needs YAF's installation wizard before the normal journey.
Application data must be writable for mail and Lucene indexing. Image resizing,
avatars, attachments, private messages, multi-board creation, virtual-directory
hosting, upgrades and network mail remain unassessed. Runtime support belongs to
[compatibility](../../docs/dev/compatibility.md).

## Linux workflow

The smoke container shares the PostgreSQL container's namespace. Listen on 15432
inside it to match the staged connection string; use a fresh database for installation.

```text
docker run -d --name rehost-yaf-pg-linux -e POSTGRES_USER=yaf \
  -e POSTGRES_PASSWORD='Rehost!Dev2026' -e POSTGRES_DB=yafnet \
  postgres:17-alpine -c port=15432
SMOKE_DOCKER_ARGS='--network container:rehost-yaf-pg-linux' \
  eng/app-linux-smoke.sh YAF 5087
docker rm -f rehost-yaf-pg-linux
```

The URL-only smoke cannot replace its host process. To check persistence, replace
that process with the same key, database and cookie jar, then verify signed-in
access and retained forum content.
