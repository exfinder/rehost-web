## What this is

The first public developer alpha of Rehost WebForms: a port of ASP.NET Web
Forms and `System.Web` from Microsoft's Reference Source to .NET 10, with a
Kestrel host, consumed as NuGet packages. A C# Web Application Project runs
with its markup, code-behind and `Web.config` unchanged, beside the legacy
project that keeps building on .NET Framework. See
[getting started](../getting-started.md).

Not in this release: production deployment guidance, a Web Site project
template, automatic migration of `packages.config`, and further application
ports. [ROADMAP.md](../../ROADMAP.md) owns what follows.

## Packages

Ten packages at `0.1.0-alpha.1`; internal dependencies resolve to that same
version, third-party dependencies keep their upstream versions.

## Exercised journeys

Advertised for this release:

- **The Visual Studio Web Forms template** (`apps/WebFormsApplication`):
  default document and postback, Friendly URLs and the `.aspx` redirect,
  script and style bundles, static files, mobile master and view switching;
  built from the template package outside the repository, run, and published
  with `Web.Release.config` applied.
- **YAF.NET 3.2.16 on PostgreSQL 17** (`apps/YAF`): installation through the
  application's own wizard, then fifty-nine checks: guest, member and
  administrator journeys through registration mail, topics, replies and
  moderation, the Web API controller over the recompiled `System.Web.Http.WebHost`,
  and Lucene search finding the topic the run posted. Its seven `App_Browsers`
  files compile at activation and shape `Request.Browser`. Cookie and content
  persistence across a process replacement is verified by hand. Its
  substitutions and what is not exercised are listed in its
  [README](../../apps/YAF/README.md) and its
  [provenance record](../provenance/yafnet.md); they are part of the claim.

Historical, passed during development and not rerun for this candidate unless
the build record says so: the Identity template and Wingtip Toys against SQL
Server, eShopLegacyWebForms on mock data, and the AJAX Control Toolkit sample
site as a Web Site project. Their READMEs under `apps/` record what each
proved and when.

## Known limits

[Compatibility](../compatibility.md) is the support map and is the only place
a claim is made. The rows most likely to be met first:

- Anything that needs Windows, IIS, the registry, COM or DPAPI is not part of
  the portable runtime and fails with an explicit message where reached.
- Libraries bound to Microsoft's strong-named `System.Web` must be
  recompiled; there is no binding redirect.
- Visual Basic pages, XSD typed data sets and `.wsdl` build providers are
  unsupported; Dynamic Data is unassessed.
- Partial trust and CAS policy are unsupported; the runtime is full trust.
- The Web Site model runs but the template and publish packaging cover the
  Web Application Project only.
- Legacy serialization and resource payloads are trusted-input compatibility,
  not a security boundary.
